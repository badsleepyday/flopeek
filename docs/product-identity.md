# Product identity

## Canonical public identity

**Flopeek** is the product, repository, npm-package candidate, and CLI name for
this public Core. Its public descriptor is:

> **Versioned change context for developers and coding agents.**

Use the descriptor with the name on first reference in product material. It
states the narrow product promise: Flopeek builds bounded, versioned static
technical context before and after a source change so a developer and a coding
agent can inspect the same evidence and tell when it is stale.

Do not position Flopeek as a general SDLC suite, an autonomous coding agent, a
runtime tracer, a business-process model, or proof that a change works. The
supported product path is local scan, bounded Flow Lens, change/impact context,
and resolvable Context Refs.

## Name and distribution boundary

The maintainer selected **Flopeek** on 2026-07-25 after a point-in-time
technical availability check: the unscoped `flopeek` name returned no package
from the public npm registry, PyPI returned no `flopeek` project, GitHub search
returned no exact-name repository, and public web search returned no exact-name
product. This is a candidate-name decision, not a reservation: only an
authorized npm publish can establish npm ownership.

The visually similar but differently spelled name **Flowpeek** is already used
by unrelated public products, including an analytics site and a Chrome
extension. Flopeek must not claim affiliation with them or reuse their product
material. This document does **not** claim trademark clearance, domain
availability, or exclusive rights. A maintainer must obtain and record any
jurisdiction-specific legal advice required for its intended distribution
before promoting a public beta or stable release.

Flopeek writes local state only under `.flopeek/`.

## Writing rules

- Write `Flopeek` in product prose, `flopeek` for the package/CLI, and
  `Flopeek Core` only when distinguishing the public Core from a private
  overlay.
- Use “versioned change context” as the primary category, not “knowledge
  graph”, “SDLC platform”, or “AI code agent”. Those terms may describe
  implementation or adjacent capabilities but are not the public promise.
- Pair capability language with the evidence boundary: static relationships are
  not runtime order or proof of successful behavior.
- Do not present the npm name check, repository name, or this document as a
  legal clearance.
