# Product identity

## Canonical public identity

**Flowpeek** is the product, repository, npm-package candidate, and CLI name for
this public Core. Its public descriptor is:

> **Versioned change context for developers and coding agents.**

Use the descriptor with the name on first reference in product material. It
states the narrow product promise: Flowpeek builds bounded, versioned static
technical context before and after a source change so a developer and a coding
agent can inspect the same evidence and tell when it is stale.

Do not position Flowpeek as a general SDLC suite, an autonomous coding agent, a
runtime tracer, a business-process model, or proof that a change works. The
supported product path is local scan, bounded Flow Lens, change/impact context,
and resolvable Context Refs.

## Name and distribution boundary

The unscoped `flowpeek` npm name returned no package from the public npm
registry during the 2026-07-25 naming check. That is a point-in-time registry
observation, not a reservation: only an authorized npm publish can establish
ownership. The package has public beta metadata, but its standard publish path
is blocked by an exact approval record until the separate public-beta release
decision is granted.

Public web research also found unrelated products using the name FlowPeek/
Flowpeek, including a Chrome extension and an analytics site. This document
does **not** claim trademark clearance, domain availability, affiliation, or
exclusive rights. A maintainer must make and record the jurisdiction-specific
legal and brand decision before any public beta or stable release is promoted.

## Writing rules

- Write `Flowpeek` in product prose, `flowpeek` for the package/CLI, and
  `Flowpeek Core` only when distinguishing the public Core from a private
  overlay.
- Use “versioned change context” as the primary category, not “knowledge
  graph”, “SDLC platform”, or “AI code agent”. Those terms may describe
  implementation or adjacent capabilities but are not the public promise.
- Pair capability language with the evidence boundary: static relationships are
  not runtime order or proof of successful behavior.
- Do not present the npm name check, repository name, or this document as a
  legal clearance.
